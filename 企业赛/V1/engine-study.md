# C 发动机寿命的阶段对照

校赛 V2 正式报告的 C 平均提升为 0.883636，最差阶段为 −1.433230。平台提供的单次预测输入有 21 路传感器与 3 项运行设置。公开回放使用每台发动机的时间四分位检查健康初期、中期和临近失效的偏差。这些阶段是开发代理，平台使用自己的漂移流。

**候选设计。** 对训练数据按运行设置划分工况，在工况内标准化传感器，再学习相对 CPU 检查点的寿命残差。已有方法采用 48 单元、20 个 epoch、最大 65 循环的单次残差。开发中比较了增大网络、缩短训练、收缩白化后的随机特征回归、用岭回归重新求最后一层和寿命分位带修正。2026 年的预处理消融报告了不同 C-MAPSS 子集的敏感传感器差异，近期的工况归一化研究建议同时检验 RMSE 与非对称代价。这两项工作支持按工况和按阶段拆解误差的方法选择。[预处理消融](https://doi.org/10.1016/j.array.2026.100919) · [归一化与评分权衡](https://arxiv.org/abs/2611.28759)

最终头保留 48 单元，对最多 2,048 个等距抽取的本轮训练输入求预测的 35% 和 65% 分位。带内保持原估计，带外根据预测距边界的距离做温和扩张。系数为 0.2 乘以截在 [0.15, 0.7] 的训练标签标准差与训练预测标准差之比减一。额外调整限制在 ±25 循环，下界为零。这样可缓和平方损失把健康期与临近失效估计都拉向中间值的影响。权重中仅增加三个浮点数。该调整以寿命预测为唯一分段依据。部署时一次只读取当前授权输入，无需知道真实寿命、发动机身份或此前航段。

**公开漂移流开发。** 初始模型只读取各训练发动机的前 55% 时间记录，然后逐轮释放到 100%。公开验证发动机按整机分为选型和审计两部分。十轮开发按相同初始权重、划分、随机种子与模拟规划响应配对。下表均为 split 0。每轮阶段收益取相对静态起点的 RMSE 降幅，遗忘指标为历史已见阶段至今最大收益回撤，恢复延迟为变化后连续低于起点的轮数的均值。代理值以比例表示。确认划分单列于企业赛总体报告。

企业赛候选都从同一父模型续训，在这组表内实验 C 每轮重规划，寿命全局偏移固定为零，允许与静态起点按 1 或 .85 混合。门槛按训练探针的四个寿命分位组测父子模型 RMSE 增量，再除以起点目标标准差。保留较严的 .10 是对平均与历史保持的折中。谱回归在保持开发数据仅前 55% 时降低了晚期误差，但随着训练数据完整，公开整机审计的 RMSE 达到 46.16，高于现有 48 单元头的 43.02，因此落选。

**冻结后的整机复验。** 从训练发动机中分别留出 unit 模 5 为 0 和 4 的整机，用其余发动机重新训练基础模型、完整拟合两个头。各折均按完整机器统计 1,000 次配对 bootstrap。下表对比独立模型头，以便观察网络修改自身的作用。这些折是本次冻结后执行的检验，校赛历史开发曾使用同一数据集。

两折最差 FD 和首末阶段 RMSE 均下降，中间两个阶段误差上升，两折总体 RMSE 的配对区间均跨零。NASA 非对称分分别由 140.85 亿降至 100.93 亿、由 109.48 亿降至 104.86 亿。此分对少量极端误差非常敏感。512 条逐样本单线程 CPU 预测各重复三次，相同训练程序下，两折 V2 分别为 38.3、40.6 微秒，企业 V1 为 41.8、39.8 微秒。使用标量 min/max 运算前，企业 V1 两折为 53.1、51.2 微秒。标量优化前后两折逐阶段指标以及 bootstrap 区间一致。模型头状态从 13,256 字节增至 13,280 字节，逐样本与批量输出通过 1e-9 绝对容差验证。平台总耗时还包含模型交互、容器调度和样本传输。

**外部数据。** 在补充包 N-CMAPSS DS02-006 的公开开发分区，每 128 个采样点取一条，使用 14 路实测传感器和 4 个飞行变量。基于训练数据的高度四分位与马赫数中位数建立工况分组。单位 2、5、10、16 的 28,161 条用于独立重训，单位 18、20 的 12,960 条整机留出。按 CruiseBench 提供的单位、循环及循环内样本边界对齐，其中 4,417 条落在巡航区间。外部项目的测试分区未参与此实验。这是不同输入空间上对同一训练方法的外部迁移实验。[N-CMAPSS 原始论文](https://doi.org/10.3390/data6010005) · [CruiseBench 掩码及协议](https://github.com/NostalgiaJohn/CruiseBench)

**复现。** 在服务器企业赛 V1 目录启用 ai-plus Python，设置 `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1`。运行 `python -B engine_study.py internal` 比较候选，`python -B engine_study.py confirm` 重做两折复验。用 `/usr/bin/python3 -B engine_study.py extract` 从补充包提取 DS02 并对齐掩码，再用 ai-plus 环境的 `python -B engine_study.py external` 实施整机训练与评估。运行 `python -B benchmark.py C enterprise 0` 复验冻结回放。研究输出在企业赛 `work/engine`，完整回放由共用入口写入 `work/replay`。
