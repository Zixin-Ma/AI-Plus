# V7 控制器对照实验

同一种候选排序规则在工业模型升级前后出现了不同的结果。A 的相对尾部收益项在相同 42 对开发流上，配 V6 专家时将最低阶段收益提升 1.716 个百分点，配 V7 专家时反而降低 0.965 个百分点。两个版本的 B 专家都对只惩罚回退的规则有正向平均反应，但 V7 的收益集中在一条流。冻结控制器保留原候选排序，并把已通过本地硬门限的选项明确告诉模型。

## 计算快速路径与旧版本对齐

固定 V6 的气体、轴承、发动机专家和决策输入，比较原 V6 运行程序与 V7 控制器的 control 设置。A 的宏 F1 在一次比较中复用验证类别频数和 argmax 结果；部分重复的基线和候选计算只做一次。对齐时逐轮检查训练、选择及审计行指纹，比较候选分数、逐组指标、收益、决策、权重、重新规划、字节数及调用记录。下列流全部来自 0–19 号开发切分。

| 对照来源 | 可对齐流数 | 成对轮次 | 逐轮一致项 | 差异 |
|---|---:|---:|---|---|
| 本轮重新运行原 V6，相同数据指纹 | 66（A 30、B 30、C 6） | 660 | 全部可比结果数值和决策；各组宏 F1 / RMSE、阶段收益和分数的最大绝对差均为 0；数据指纹相同 | 全部轮次 CPU 计时不同；原版记录可选 prediction_us，控制器试验关闭了该计时 |
| 交叉核对上版 V6 已存档流 | 72（A 34、B 34、C 4） | 720 | 所有共有的逐轮分数和决策一致 | 旧存档缺三个行指纹字段。两侧 CPU 不同；旧存档有 prediction_us |

两个对照共享部分协议和随机种子，因此分别统计。66 条流的逐轮 CPU 中位数为 0.1721 → 0.1867 秒；与历史存档的 72 条比较为 0.1775 → 0.1701 秒。这组多个进程并发的实验用于核对语义，计时方向随参照批次变化。

## 以 V6 专家筛选候选排序

候选首先满足原有硬门限。额外排序项在已释放训练集与当前验证集之间寻找变化明显的特征，最多选三条相关系数不超过 0.9 的轴，分别按四分位分组。A 使用逐行分类错判，B/C 使用逐行平方误差。每个至少五行的组比较同一行上父模型与候选的损失差，经过稀疏收缩后取得分最低组，再跨轴取均值。生产归档中的 `PAIRED_RISK` 保持空映射。

| 变体 | 第二排序分量 |
|---|---|
| control | 原验证排序 |
| lower | 组损失改进率减 0.5 个标准误，外部权重 0.35 |
| penalty | 只累加最低组中为负的改进率，权重 0.4 |
| relative | 用父模型在该组内累计的损失而非行数衡量改进率的支持度，权重 0.5 |
| strong | 与 relative 相同，权重增至 1.25 |

下表在每个任务四条路线都运行过的相同分组上比较。A/B 各有 12 对流，即 drift、fresh、schedule、transfer 四协议各三种切分；C 有 6 对流，即 drift、schedule、transfer 各两种。相对 control 的差值中，阶段收益和回撤的单位为百分点，恢复延迟单位为轮。回撤和延迟越低越好。

| 任务 / 路线 | 平均收益 Δ | 最低收益 Δ | 回撤 Δ | 恢复延迟 Δ | 部署名称改变轮数 |
|---|---:|---:|---:|---:|---:|
| A lower | 0 | 0 | 0 | 0 | 0 / 120 |
| A penalty | 0 | 0 | 0 | 0 | 0 / 120 |
| A relative | +0.483 | +1.897 | −5.409 | 0 | 4 / 120 |
| A strong | +0.483 | +1.897 | −5.409 | 0 | 4 / 120 |
| B lower | +0.062 | +0.464 | −0.303 | +0.017 | 2 / 120 |
| B penalty | +1.681 | +2.893 | −3.642 | −0.250 | 9 / 120 |
| B relative | −1.896 | −3.833 | −4.931 | +0.267 | 6 / 120 |
| B strong | −0.205 | −1.097 | −8.199 | 0 | 14 / 120 |
| C 各路线分别与 control 比 | 0 | 0 | 0 | 0 | 各 0 / 60 |

C 的 lower、penalty、relative 各有 2 轮候选权重改变，strong 有 3 轮，部署名称、实际逐组指标和每轮 NASA 代价均与 control 相同。B 的强 relative 在 5 对流中提高最低收益、2 对下降、5 对持平，平均最低收益仍为负，说明只看胜负次数会漏掉较大的损失。旧专家扩充比较中，A relative 在 48 对流上的平均/最低为 +0.505/+1.558 个百分点，最低胜平负 5/39/4；B penalty 在 48 对流上为 +0.405/+0.790 个百分点，最低胜平负 6/41/1。

## 换用 V7 专家的交叉检验

对每条流固定相同公开样本、协议及专家，仅变更排序，再比较 V6 与 V7 上的效果。A 取两个版本的共同 42 对，B 取共同 18 对。

| 路线 / 工业专家 | 流数 | 平均收益 Δ | 最低收益 Δ | 回撤 Δ | 延迟 Δ |
|---|---:|---:|---:|---:|---:|
| A relative / V6 | 42 | +0.567 | +1.716 | −2.487 | 0 |
| A relative / V7 | 42 | −0.046 | −0.965 | +1.172 | 0 |
| B penalty / V6 | 18 | +1.168 | +1.837 | −2.071 | −0.167 |
| B penalty / V7 | 18 | +0.070 | +0.394 | +0.087 | +0.007 |

A 的全部 48 对 V7 开发比较中，最低收益 −0.996 个百分点，1 胜、40 平、7 负。每个协议有 8 对，最低收益差分别为 schedule −1.944、trace −2.342、transfer −1.033、official −0.393、drift −0.261、fresh 0 个百分点。B 的 18 对中，schedule 六对与 transfer 六对的最低收益均持平，fresh 六对中只有一条改善，该协议最低收益平均 +1.182 个百分点；transfer 的平均收益下降 0.325 个百分点。B 的部署名称总共改变 3/180 轮。额外半权重风险分量与新工业专家组合后的收益缺少足够的跨协议一致性。

## 真实 Qwen 规划与审查

固定 V6 工业训练和三个任务的 schedule 开发流 17，每任务 10 轮。三种提示设置使用同一 Qwen/Qwen3.8-27B。逐条校验已存的请求哈希、模型名、输入/输出/总 Token；三种路线各有 38 次模型调用，实际涉及 90 个唯一请求哈希，相同请求可复用上次回执。这里的 Token 按逻辑运行计量。统计过程仅重读现有回执。

| 提示设置 | 规划输入 / 输出 | 审查输入 / 输出 | 总 Token | 相对旧版 |
|---|---:|---:|---:|---:|
| 旧规划 + 旧审查 | 1,748 / 448 | 3,355 / 349 | 5,900 | — |
| 旧规划 + 显式合法选项审查 | 1,748 / 448 | 2,068 / 354 | 4,618 | −21.73% |
| 压缩规划 + 显式合法选项审查 | 1,490 / 65 | 2,064 / 396 | 4,015 | −31.95% |

三种设置各有 8 次规划和 30 次审查。仅更改审查时，30/30 轮的实际部署、候选族、候选权重及是否重规划完全一致，且三个任务各自的平均收益、最低收益、回撤和恢复延迟均相同。继续压缩规划，A、B、C 分别有 4、2、2 轮改变部署，任务间出现取舍。

| 任务 | 原版或只改审查：平均 / 最低 / 回撤 | 再压缩规划：平均 / 最低 / 回撤 | 恢复延迟，两种设置 |
|---|---|---|---|
| A | 39.877% / 9.234% / 0.000 pp | 41.079% / 9.234% / 14.132 pp | 0 轮 |
| B | 0.411% / −4.346% / 4.883 pp | −0.084% / −4.859% / 3.319 pp | 1.5 轮 |
| C | 12.016% / 6.181% / 1.255 pp | 12.964% / 6.146% / 0.543 pp | 0 轮 |

相同输入的提示实验还有两组。开发组每个设置 12 个请求：旧审查解析通过 12/12、合法选择 11/12；压缩审查为 12/12、11/12；只列合法选项的第一种措辞为 9/12、9/12；显式告知“全部列出选项已通过，唯一可选时回复保留父模型”后为 12/12、12/12。固定的另一组 18 个审查输入中，旧审查合法选择 10/18，使用 2,322 Token；显式审查合法选择 18/18，使用 1,001 Token。这里统计的是模型原始回复是否符合门限，实际部署仍有本地校验。单一真实回放种子可以区分这两处提示改动，不能据此推算正式积分。

## 复算

在 BJTU 仓库根目录执行以下命令。结果写到 `企业赛/work/v7/controller-audit.json`。程序显式枚举 0–19 号开发流，不导入训练模块，也不调用模型、平台或网络。

```bash
python -B 企业赛/V7/controller_audit.py
```

原始输入包括 `work/v7/controller/{v6,v7}` 中逐路线的流、`work/v7/replay` 的原 V6 对照、`work/v6/replay` 历史核对，以及 `work/v7/cloud` 中相同输入的提示实验、整流基线、两种消融和请求回执。JSON 保存每种协议的成对样本数、各指标基准与实验均值、胜平负、部署变化及 Token 拆分。全部比较基于相同公开数据的重复切分；同一条公开记录可出现在多个协议中。
