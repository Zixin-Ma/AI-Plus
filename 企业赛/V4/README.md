# 企业赛 V4 · 工业漂移下的气体识别与剩余寿命预测

V4 从企业 V3 迭代。Qwen/Qwen3.8-27B 经赛方宿主网关执行规划与裁决，工业模型在离线容器中续训并逐条预测。本版本保留了轴承的逐轮部署决策，改变了气体和发动机的任务头，并对三项任务都实现了单条推理预计算。分支实验、补充数据适配、未采用的方法及重现实例分别见同目录的《气体实验》《轴承实验》《发动机实验》。

## 冻结后的公开复验

两版采用相同初始条件、训练行、选型行和审计行。开发安排共 78 对十轮流；冻结后按 3 个新顺序 × 3 项任务 × 4 套协议另跑 36 对。总计 114 对、228 份独立运行记录、2,280 轮。开发顺序 0–7 用于比较方案。顺序 8–10 的运行时与输入指纹先行登记，审计使用新分组及访问顺序。所有顺序共享官方公开数据，开发拆分 0、1 的审计并集已覆盖公开验证行。三份固定确认顺序可测顺序与分块敏感性，不能提供新设备总体的置信区间。

|---|---:|---:|---:|---:|
| 逐批扩大训练池 | 13.51% → 13.55% | −2.85% → −2.79% | 14.26 → 14.84 | 0.222 → 0.208 |
| 回访更换选型样本 | 13.53% → 13.36% | −4.66% → −5.22% | 18.00 → 18.96 | 0.250 → 0.208 |
| 回访更换样本、实测挑选候选或历史产物 | 13.58% → 13.52% | −3.34% → −2.99% | 20.84 → 21.56 | 0.264 → 0.222 |

A 用 Macro-F1 的相对增加，B/C 用 RMSE 的相对下降。每流十次部署中取最低阶段收益。回撤是已见阶段相对历史最高收益的最大降幅。恢复从阶段切换开始计时，到收益达到零结束，若该阶段结束仍未恢复则截尾。每轮先按训练与可见选型样本完成裁决，随后在四个隔离阶段上评估。研究回放用固定规划/评审或按真实测量选择的确定性评审。公开首轮另有六份真实模型回执。赛方隐藏阶段、35 分换算和部署费用仅在平台正式评测时可观测。

## 分支改动与证据

**A 气体。** 同一样本内按稳态幅度归一化瞬态响应，用每类至多六个原型拟合辅助分类证据。根据前两类的相对证据决定附加分量，部署无需日期或同批其他样本。原 24 日窗口 Macro-F1 为 0.5334 → 0.6025（409 条）；本轮预先冻结的末 8 日为 0.6385 → 0.6458（143 条，按日配对提升区间 −0.0003 至 +0.0245）。末 8 日曾计入 V3 的 24 日汇总。另一仪器 DS-PS 的 72 条留出为 0.5077 → 0.5664。官方完整公开首轮由 0.8623 提高至 0.8890，但冻结复验中滚动更换选型样本时，A 各流最低收益均值由 +7.01% 降至 +3.64%。

**B 轴承。** 将固定的频率、插值结点、寿命分位及混合常数提前到加载阶段，保留 V3 计算规则与工况回退。380 对回合的部署选择和 7,590 个核对数值均相同。冻结增长池中最差收益均值均为 −14.33%，最差单流均为 −31.71%。顺序改善和绝对收益需分开解释。公开首轮 RMSE 均为 507.8345 分钟。更正 V3 报告中 FEMTO 的比较基准：冻结头的六设备宏均/最差 RMSE 为 92.66/203.27 分钟，旧值 87.73/189.29 来自采用 2.5% 末端覆盖门槛的研究候选。逐折数值见轴承实验。

**C 发动机。** 训练时用已释放寿命的第 20、45、70 百分位提供三个辅助分类目标，部署只读连续寿命预测。若父模型当前最弱公开组落后静态起点，且按静态预测分出的各寿命带均低估，控制器才允许试验有限上调。上调幅值上限为训练残差绝对值中位数的 15%，训练预测寿命从第 20 至第 65 百分位时逐步开放。不同偏移幅度、无门禁校正、静态回退和分组惩罚均做了配对对照。冻结回访换样本的各流最低收益均值 −2.33% → −0.64%，三个顺序分别改善。增长池各流最低均值 −2.15% → −1.89%，其中单一最低 −2.90% → −3.24%。DS02 两台整机测试 RMSE 8.37 → 7.93 循环，NASA 非对称代价 16,632 → 15,249。巡航样本是同两台设备的子集，内部整机折与固定公开池的高估代价同时见分支实验。

这些方法的参考包括 2026 年气体传感器跨日漂移的置信校准研究、退化阶段识别研究、CruiseBench 巡航掩码和 ONNX Runtime 的常量折叠与算子融合。V4 在 NumPy 实现等价预计算，镜像运行时使用 SDK 1.0.4、单线程 NumPy 2.2.6 和 Python 3.12。[跨日漂移研究](https://doi.org/10.1002/cem.70148) · [退化阶段研究](https://doi.org/10.3390/s26227305) · [CruiseBench](https://github.com/NostalgiaJohn/CruiseBench) · [ONNX Runtime 优化文档](https://onnxruntime.ai/docs/performance/model-optimizations/graph-optimizations.html)

## 复现与部署

服务器项目根目录下的 `校赛/work` 提供 SDK、三份原始工业模型、公开 train/validation、基础镜像及依赖 wheel。补充数据位于 `Supp_Datasets`，原始文件留在服务器。资格复验需保留同一仓库中的 V3 源码。证据包中的 `protocol.json` 与 `freeze.json` 对应 `企业赛/work/v4/`。计算结果、实验记录及发布包写在该忽略目录。以下命令在 `企业赛/V4`、服务器 ai-plus 环境执行。

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 BASELINE_CPU_THREADS=1 PYTHONDONTWRITEBYTECODE=1
python -B test_loop.py
python -B test_release_controls.py
python -B test_v3_policy.py
python -B test_v4_serving.py
python -B controller_v4_study.py v4 screen --routes original coherent15 taper15 up
python -B qualify.py freeze
python -B qualify.py dev
python -B qualify.py confirm
python -B qualify.py summary
python -B verify_pairs.py
python -B build_image.py
python -B verify_image.py
for k in A B C; do python -B resource_bench.py "$k"; python -B serving_study.py suite "$k"; done
python -B sdk_latency.py
/root/miniconda3/envs/M2Gaze/bin/python -B release.py
```

`verify_pairs.py` 从每轮的四组指标复算收益、回撤和恢复，并检查两版样本计数和轴承等价性。`resource_bench.py` 在相同 CPU 核交替完成十轮更新及同一组单行预测。`serving_study.py` 每组使用 5 个种子、每次随机取 600 行，分别测进程内完整 JSON 路径、预绑定入口、专家预计算及旧检查点等价性。`sdk_latency.py` 用已导出的 V3/V4 镜像、普通容器用户和真实 SDK 持久预测进程，每次写一行并等待完整响应，另记进程启动至首个响应时延。两组工具均保留同一 V3 检查点更换运行时的对照，并测两版各自最终产物。换机后时延需在目标硬件重新测量。

镜像标签为 `bjtu-rsi:enterprise-v4`，宿主走 `describe`、`train`、`predict`。SDK 输入一条 JSON 后直接回传六类概率或非负寿命。候选、父产物和重新实测的授权历史产物按 ID 及摘要追踪。服务端重复使用同一不可变产物时可复用已准备的预测函数；切换产物会重新加载。镜像集成测试每任务跑三轮并强制验证父产物回退。运行 `public_smoke.py A`、`B`、`C` 会检查请求摘要，精确匹配时复用回执，缺少缓存时产生付费模型调用。本轮新产生两次裁决共 204 Token，其余四份来自相同请求的已有回执。工业现场应结合报警阈值、设备寿命高估代价与操作规程决定检修动作，回退时按发布清单恢复已批准的镜像与模型产物。
