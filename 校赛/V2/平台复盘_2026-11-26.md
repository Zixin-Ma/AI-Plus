## 已查明的实现与验证缺口

1. 正式 V2 的 B 和 C 共 20 轮，configuration 中 worst_group 全部为 all，worst 与 primary 全部相同。projection 在公开行缺少 bearing 或 source_subset 元数据时默认设为 all。这使开发时按设备或子集实施的保护在平台退化为整体指标保护。修复应采用协议始终提供的输入定义可部署分组，例如 C 的运行设置和 B 的训练集振动强度分位。分组语义应如实记录为工况或信号区间。训练集拟合阈值，验证集只做测量。新增分组仍需检验与赛方最差阶段的关系。
2. 正式 V2 的 A 训练行从445增至3200，C从113089增至117909，验证池也变化。开发轮换回放固定了训练池，无法覆盖新训练数据到来后的重拟合与遗忘。后续验证须同时按时序释放训练和验证样本，保留从未参与选择的末段，并按训练内设备整组留出重新建起点。
3. 正式 V2 的 B 先 refit，一次采用，随后九轮都选 adam、九次被拒绝。C 九轮 refit，仅头两轮采用。A 九轮 refit，六次采用。工具选择没有有效避开重复的低收益试验。规划器需要展示各工具近期拒绝率、数据是否新增及上次 CPU 成本，并用实测比较约束试验预算。
4. 试运行 CPU 总量从2502.535增至2977.183秒，增加18.97%。Token 从22849增至30821，增加34.89%。开发首轮进程及单预测函数的计时仅覆盖部分工作，无法代表平台累计用量。新增两次规划及决策、重复验证、容器运行和传输都可能影响实际费用；现有队伍报告未拆分这些成本，不能确定单一原因。后续必须用完整协议入口测量多轮、逐样本预测与两次模型交互，并以平台回执最终校验。
5. 当前守门只要求优于父模型及其最差组，未设置跨阶段静态参照的保护。父模型本身在新阶段退化时，局部正收益仍可能低于静态起点。需要对合法保存的起点/历史产物进行同一当前公开池的重测，比较静态退化保护是否有效。保护不能保证隐藏阶段达标。
