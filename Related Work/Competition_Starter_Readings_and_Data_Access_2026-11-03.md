**智训引擎：官方数据获取与初学团队入门工作**

**先明确项目的学习目标**

赛题要求在工业漂移数据流上完成“监测—诊断—实验优化—评估上线—回滚”，同时控制算力、标注与大模型 Token 消耗。规则说明数据包较小、提供预提取特征，基础任务普通 CPU 可完成。初学团队最先需要建立的是可靠、可测量的更新闭环，再增加策略自改进。以下推荐按比赛适配度、学习门槛、能否形成一个小实验排序，属于针对本项目的建议，不是文献影响力排名。[官方赛题页](https://bjcsaiic.zsyqkj.com/topics/2026/9)

**二、最值得先读的五篇工作**

第一阶段建议只围绕五篇形成可运行的组件。它们覆盖什么时候更新、如何更新、怎样低成本实验，以及怎样改进策略。原论文任务与工业任务并不相同，下面的项目映射均是本文建议，不能当作论文已经验证工业迁移。

| 顺序 | 工作 | 解决的项目问题 | 学习负担（本文判断） | 首个产出 |
| --- | --- | --- | --- | --- |
| 1 | ADWIN，2007 | 什么时候需要考虑更新？ | 中，先理解直觉与调用 | 漂移信号和模型误差的时间图 |
| 2 | Adaptive Random Forest，2017 | 漂移后如何渐进地更新模型？ | 中 | 一个有效的在线学习对照 |
| 3 | Optuna，2019 | 有限预算下如何做实验？ | 低至中 | 可复现、有预算上限的调参实验 |
| 4 | Reflexion，2023 | 怎样把失败经验用于下次决策？ | 低至中 | 有结构、有版本的实验记忆 |
| 5 | GEPA，2025；ICLR 2026 | 怎样根据执行反馈改进策略提示词？ | 中 | 可被验证、保留或回退的策略更新 |

**1. ADWIN：理解漂移检测，是第一篇**

原文：[Learning from Time-Changing Data with Adaptive Windowing](https://epubs.siam.org/doi/abs/10.1137/1.9781611972771.42)。实作入口：[River ADWIN 文档](https://riverml.xyz/latest/api/drift/ADWIN/)。

核心直觉是让窗口长度适应数据变化：稳定时保留更多历史，检测到变化时缩短窗口。先读问题定义、窗口切分比较和算法流程，证明部分可以放到第二轮。

本项目的小实验：构造或使用带时间顺序的特征流，比较静态模型、固定周期更新、ADWIN 触发更新。记录累计与分段任务指标、更新次数和运行开销。若使用模型误差作为输入，必须等真实标签按协议可见后才能计算；若只监测特征统计变化，报警仅能支持输入分布变化，不能单凭它认定模型性能已经下降。

初学时不需要从零复刻全部桶压缩实现。先利用成熟实现验证输入信号、触发逻辑与成本是否正确，再深入复杂度和统计保证。

**2. Adaptive Random Forest：建立一个能适应漂移的强对照**

原文：[Adaptive random forests for evolving data stream classification](https://link.springer.com/article/10.1007/s10994-017-5642-8)。实作入口：[River ARFClassifier 文档](https://riverml.xyz/latest/api/forest/ARFClassifier/)。

ARF 将随机森林思想用于演化数据流，通过重采样及适应机制应对变化。阅读重点是在线更新、漂移后的候选树/替换机制，以及 test-then-train 与延迟标签评测，而不是先通读所有实验表。

本项目的小实验：在分类任务成立的前提下，对比静态模型、固定周期重训与 ARF，观察突变、缓变和重复工况下的恢复速度及计算开销。若官方任务是剩余寿命等回归问题，应改用适合的回归模型和指标；这篇分类论文不自动成为回归方案的有效性证据。

它首先承担“模型层适应基线”的角色。使用了漂移检测和在线更新，并不代表策略层已学会自我改进。

**3. Optuna：用有限预算获得可信的实验结果**

原文：[Optuna: A Next-generation Hyperparameter Optimization Framework](https://arxiv.org/abs/1907.10902)。实作入口：[官方采样与剪枝教程](https://optuna.readthedocs.io/en/stable/tutorial/10_key_features/003_efficient_optimization_algorithms.html)。

先理解 objective、trial、search space、sampler 与 pruner 的关系。对比赛而言，重点是比较方案时具有一致的实验预算，并及时停止明显无效的候选。非迭代估计器未必能直接使用逐步剪枝，需要有真实、可比较的中间评估信号。

本项目先搜索少量可解释参数，例如学习率、历史窗口大小、重训频率、漂移阈值或模型复杂度。优先建立随机搜索对照，并固定时间/候选/标签预算；不要因为 Agent 提出了更多实验，就认定它更有效。

训练与选择窗口必须遵守时间顺序。可以在公开历史流中构造多个开发片段，但每个模拟时点只能使用当时协议允许的信息。最终保留独立的时间区间或任务族检验，不把所有公开数据反复调到最优后报告作泛化结果。

**4. Reflexion：最容易理解的 Agent 经验积累机制**

原文：[Reflexion: Language Agents with Verbal Reinforcement Learning](https://arxiv.org/abs/2303.11366)。代码：[作者仓库](https://github.com/noahshinn/reflexion)。

重点阅读 Actor、Evaluator、Self-Reflection 与 episodic memory 如何连接。理解“任务反馈 → 反思 → 下一次执行”即可先做小原型，不必照搬原论文的问答或游戏环境。

在本项目中，每轮保存“当前工况证据、采用动作、实际结果、消耗、保留/回退理由”。例如“当前是少数类错误增加，全面重训未见收益”是一条待后续验证的经验，不应被立即升级为对所有工况适用的永久规则。对照组应包含无记忆、仅结构化历史、加入语言反思三种设置。

工业模型真实指标和资源计量应由程序计算，大模型负责组织诊断与提出动作。单靠大模型给自己打分，不能替代真实性能评价。正式使用的驱动模型须满足赛题对 PyTRiO 的要求；开发阶段可先用固定动作或模拟策略验证接口，不假定已获得额度。

**5. GEPA：最值得作为策略层改进主线的工作**

原文：[GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning](https://arxiv.org/abs/2507.19457)。代码：[gepa-ai/gepa](https://github.com/gepa-ai/gepa)。

GEPA 从执行轨迹中提取反馈，产生并筛选提示词修改，保留具有互补优点的候选。对初学团队，它提供了比直接训练大型 RL 系统更容易开始的策略优化接口；搜索仍有 Token 与评估成本，不能因为不更新权重就忽略成本。

建议只允许改一个受限的“更新决策策略”：什么时候保持现状、什么时候申请标签、选择何种训练窗口、何时启动有限预算调参、如何判定上线和回退。训练器、数据访问规则、总预算、最终审计及回滚底线保持明确的程序约束。

首个实验对比固定规则、一次 LLM 重写、固定 LLM 提示词、GEPA 优化提示词，使用相同可用信息和预算。衡量的是独立流片段上的任务表现与总成本，不是反思文本长度。若 GEPA 实际作用于更新决策策略，可称作策略层自动优化；是否证明“改进器更会改进”，仍需额外对照。

**三、两篇配套阅读：让方案更可信、更接近近期研究**

[Rethinking the Evaluation of Harness Evolution for Agents](https://arxiv.org/abs/2607.12227)应在写实验方案时就读。它提出预算匹配和搜索/测试分离的重要性，并同时报告终端任务与长程游戏的不同结论。项目映射是：Agent 必须和随机搜索、固定周期更新及一次重设计在可比预算下比较。

[RRSI: Regularized Recursive Self-Improvement of Agent Harnesses](https://arxiv.org/abs/2609.24972)适合在 GEPA 原型可用后接着读。先学习限制单轮变更规模、筛查基准特化修改、剪除无效规则的思路。可以尝试把它们转为策略规则的复杂度限制和回归门槛；工业场景的收益需要团队自己验证。

Skill∞、Hyperagents、Self-HPO 等适合作为第二阶段的拓展参考。当前阶段不建议把完整大型系统复现作为第一个里程碑；优先顺序来自本项目的 CPU 起步条件、评测门槛与预算约束，并非否定这些工作的研究价值。

**四、从初学开始的实际安排**

建议按可验收成果推进，而不是要求所有人先把论文读完：

1. 数据与评测协议组：领取官方公开集/SDK，整理特征、标签时点、费用和评分接口；在获批信息边界内建立时间顺序评测器。
2. 模型与漂移组：实现静态、固定周期与漂移触发基线；先产出一张“性能—时间—更新次数”图。
3. 实验与策略组：用 Optuna 建立有上限的候选实验，记录成本和失败；随后增加 Reflexion 记忆。
4. 共同推进：用 GEPA 改进受限策略，在留出流片段做成本匹配比较，并验证上线失败时可恢复。

三人团队可合并数据评测与实验记录职责；五人团队可把部署/日志/镜像单独分工。建议的里程碑是：

| 阶段 | 完成条件 |
| --- | --- |
| M0 | 已确认官方数据、标签协议、静态基线、预算与提交方式 |
| M1 | 静态模型与固定周期更新均可从头跑完，结果可重复 |
| M2 | 漂移触发方案与在线适应基线有清晰的成本—效果对照 |
| M3 | 候选模型的评估、保留、上线与回退形成闭环 |
| M4 | 加入经验记忆与策略优化，在留出流上验证额外价值 |
| M5 | 离线镜像、失败恢复、完整实验记录与最终报告可交付 |

在官方数据尚不可用时，可用合成漂移流练习 M1—M3 的接口与流程，明确将结果标记为工程验证；不能将其作为官方比赛成绩或特定工业任务效果。正式模型选择和资源配置应在获取 M0 信息后调整。
