**RSI 研究全面梳理：从自我修正、系统进化到改进器的递归优化**

检索截止：2026 年 11 月 3 日（Asia/Shanghai）。整理日期：2026 年 11 月 3 日。

**核心判断。** 当前公开研究已经证明：AI 能在特定环境中持续积累可复用的技能、改写 Agent 的运行系统、生成训练数据，并在部分实验中改进产生后续更新的机制。证据最充分的是有明确反馈、有限预算和受保护评测的局部闭环。跨领域、长期可靠且持续加速的通用 RSI，仍需要比现有单项成绩更强的纵向和因果证据。本文以“改了什么、改动是否继承、谁判断变好、未来的改进能力是否提高”四个问题组织研究。

**一、如何理解所给文章，以及需要补充的边界**

用户提供的入口是周星星的《什么是 Self-evolving / self-improving / RSI？一篇文章搞懂自进化》。知乎页面直接抓取返回 403；本次读取了明确署名并链接回同一知乎地址的[青稞社区转载版](https://www.qingkeai.online/blog/Self-evolving)。转载页标注发布日期为 2026-07-28，但本次只能确认当前可访问正文，不能将它当作该日期的不可变快照。[知乎原文](https://zhuanlan.zhihu.com/p/2065227313973825752)

文章最有用的组织方式是按优化对象区分 Artifacts、Harness、Model。它在结尾进一步把“变好”与“变好的能力也变好”区分开。这两层含义应贯穿全文：三分法回答更新对象，严格 RSI 还要求分析反馈如何进入后续改进过程。本文保留这个起点，进一步展开改进器、验证器、预算与泛化。[文章转载版](https://www.qingkeai.online/blog/Self-evolving)

下面五点是结合原始研究后的分析，而非直接转述文章：

| 需要区分的问题 | 本文采用的解释 |
| --- | --- |
| 反复修改答案与系统进化 | 同一任务的答案修改通常只提高本次产物；只有进入后续任务或后继系统的持久更新，才构成系统层的累积。 |
| 多 Agent 与自我改进 | 协作、审查和投票属于运行结构；是否自我改进取决于结构、知识或参数是否被反馈持续更新。 |
| 不改权重与低成本 | 不更新权重可以降低部署门槛，但多轮搜索、候选评估和长上下文仍可能很贵。 |
| 自训练与无需外部信息 | 不使用新增人工标签，不代表没有预训练知识、环境反馈、验证器、特权上下文或人工设定的目标。 |
| 可解释性与 RSI | 可解释性可用于定位失效与审计更新；机制解释本身还不能证明可持续的改进闭环。 |

这些边界分别可以在 [Self-Refine](https://arxiv.org/abs/2303.17651)、[Reflexion](https://arxiv.org/abs/2303.11366)、[Absolute Zero](https://arxiv.org/abs/2505.03335)、[预算对等的 Harness 评测](https://arxiv.org/abs/2607.12227)中找到具体实例。

**二、一个能比较不同论文的统一框架**

为了便于比较，本文使用如下分析记号，属于综合表述，并非某篇论文的原始定义：

Sₜ = (θₜ, Hₜ, Dₜ, Eₜ, Uₜ)

θ 是模型参数；H 是提示词、记忆、技能、工具、上下文管理与工作流；D 是经验与训练数据；E 是评估和接纳机制；U 是诊断、提案、搜索、训练与整合更新的改进机制。系统根据任务执行得到轨迹和反馈，再产生下一版系统：

Sₜ₊₁ = Uₜ(Sₜ, experience, feedback; budget)

若 U 本身进入可更新的状态，并且改后被继承为 Uₜ₊₁，就出现了更明确的自指结构。但是“U 被改了”仍是结构证据；要证明改进器有收益，还应比较新版和旧版在相同起点、相同预算、独立任务上产生改进的能力。[Hyperagents](https://arxiv.org/abs/2603.19461)和[可信 RSI 综述](https://arxiv.org/abs/2610.35193)分别提供了系统与过程层面的相关框架。

可以用下列证据梯度阅读论文。这是本文的阅读工具，不是学界统一等级，也不与 Weco 等机构的 Level 编号等同。

| 证据层次 | 必须观察到什么 | 常见混淆 |
| --- | --- | --- |
| 本次任务改好 | 一次输出或当前任务成功率提高 | 把自我纠错叫作持久学习 |
| 持久能力提高 | 后续执行继承参数、代码或经验，并在独立任务上获益 | 只在搜索使用过的题目上报告结果 |
| 改进机制被修改 | 提案、诊断、课程、验证或调度的机制也被修改并复用 | 改了更多组件就宣称递归更深 |
| 改进能力被验证 | 同等预算下，新版改进器对共同起点产生更有效的后续更新 | 用最终求解分数代替改进器能力 |
| 长期复利与加速 | 多代、跨任务族的改进效率维持或提升，计入全部成本与退化 | 从两三轮曲线外推智能爆炸 |

外部固定验证器与 RSI 可以并存。将最终评测保护起来，有助于使“变好”的含义保持可比；递归性不要求系统同时接管目标定义和最终裁判。相反，如果系统能够自行降低验收标准，分数上涨会失去解释力。

更严格的比较对象是改进器的元效用：

J(U; S₀, B) = 在预算 B 内，U 从共同起点 S₀ 产生的后继系统，在隐藏任务上的净收益。

例如，旧改进器花 100 个预算单位，把隐藏任务准确率从 40% 提到 50%；新改进器从同一个 40% 起点、花相同预算提到 55%，并在重复实验中成立，才能较有力地支持改进器收益。直接比较前一轮 50% 与后一轮 55%，会混入更强起点、累计经验与额外计算的影响。Weco 的 [ignition test](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)正是值得关注的相关尝试，但其作者明确认为证据尚不足。

**三、研究脉络：为什么今天的 RSI 成为可实验问题**

| 时段 | 关键变化 | 与当下研究的联系 |
| --- | --- | --- |
| 早期理论 | Gödel Machine 将自修改与效用证明结合 | 提出“何时允许修改自身”的规范问题；依赖公理与可证明性，不是现成工程方案 |
| 2022—2023 | 自生成推理、语言反思、技能库与可执行脚手架出现 | 从改答案发展到保留经验，并出现改进器修改自身的原型 |
| 2024 | 自奖励、自对弈和自动 Agent 设计发展 | 训练信号、运行结构开始成为自动优化对象 |
| 2025 | 编码 Agent 自改、演化算法发现、零新增数据自博弈强化 | 验证器、执行环境与候选档案支撑多轮改进 |
| 2026 | 可编辑元 Agent、Harness—Policy 联合优化、改进器预测与技能元优化 | 研究重心扩展到“如何使后续更新更有效”，并开始系统检查预算、泛化和评测漏洞 |

相关原始入口包括 [Gödel Machines](https://arxiv.org/abs/cs/0309048)、[STaR](https://arxiv.org/abs/2203.14465)、[STOP](https://arxiv.org/abs/2310.02304)、[ADAS](https://arxiv.org/abs/2408.08435)、[DGM](https://arxiv.org/abs/2505.22954)与 [Hyperagents](https://arxiv.org/abs/2603.19461)。表格表示代表性机制的演进，不宣称各时期只有这些路线。

**四、路线 A：产物与算法进化——最容易建立客观反馈的入口**

这一类系统使用 LLM 提出程序、算法或实验配置，执行后评估，再选择下一批候选。模型和搜索框架可以保持固定，优化对象是产物。

[AlphaEvolve](https://deepmind.google/discover/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)将程序生成、自动评估与演化选择结合。DeepMind 报告，它优化了 Gemini 的一个矩阵乘法内核，使该内核提速 23%，对应总体训练时间降低约 1%。这里必须区分局部算子的提速和训练全流程的收益。该结果支持“AI 生成的算法能够反哺 AI 基础设施”；是否形成进一步的递归加速，还需要测后继系统是否更善于发现下一批改进。

[Karpathy autoresearch](https://github.com/karpathy/autoresearch)提供了更易理解的实验范式：Agent 在受限训练设置里修改训练程序，按固定时长运行实验，以验证指标决定保留或回退。这使“提出假设—做实验—读结果—决定下一步”成为可重复过程。它是 AI R&D 自动化的重要组件；固定 Agent 持续改一个训练文件，单独不足以说明 Agent 的研究策略也在持续进化。

[The AI Scientist](https://arxiv.org/abs/2408.06292)把想法、实现、实验和论文写作串成更完整的研究流程。其意义在流程覆盖；论文文本、自动审稿分数、可重复的技术进步应分别评估。科研产出自动化和科研能力递归提升之间，还需要验证后继研究过程的效率与质量。

**这条路线的关键问题：** 如何从“做出了更好的算法”，走到“更好算法改善了下一轮发现算法的能力”？需要把产物部署后的效果重新接入科研或训练循环，并测量完整周期成本。

**五、路线 B：记忆、技能和经验积累——把一次成功变成以后可复用的能力**

[Reflexion](https://arxiv.org/abs/2303.11366)把执行反馈转成文字反思，并存入 episodic memory，影响后续尝试。[Voyager](https://arxiv.org/abs/2305.16291)通过自动课程、可执行技能库和环境反馈，在 Minecraft 中积累、组合与迁移技能。两者表明，不更新权重也能形成持久的系统状态。

这类研究的主要学习介质是外部表示：记忆条目、技能代码、规则或工作手册。它们易于读取和修改，也需要解决检索失败、冲突、重复、错误经验固化与上下文膨胀。技能条目数量增长本身不是能力增长，关键是后续任务中的调用是否有效、是否改善成本和成功率。

2026 年 10 月的 [Skill∞](https://arxiv.org/abs/2610.35434)进一步把“优化技能的程序”写成 meta-skill，再用同一过程优化它。作者在 83 个 SkillsBench 任务上报告 60.7% 通过率，对比人工技能 56.4% 和 SkillEvolver 54.5%。它把任务技能与改进技能分离，提供了研究元过程迁移的具体接口；长期跨任务累积仍应与单轮总体通过率分开检查。

**本文判断：** 技能元优化是研究严格 RSI 的可行切口。它具有较清晰的更新对象和版本边界，可以独立替换 meta-skill，开展旧版、新版和人工版的受控比较，无须一开始就运行昂贵的全模型训练。

**六、路线 C：Harness 进化——提示词、工作流到 Agent 代码**

Harness 是模型与环境之间的运行系统，包括工具接口、信息路由、上下文压缩、停止与重试策略、记忆管理，以及多个 Agent 如何协作。它改变模型看见什么、可以做什么，以及如何利用反馈，因此即使基础权重不变，也能显著影响性能。[Lilian Weng 的原文](https://lilianweng.github.io/posts/2026-07-04-harness/)提供了设计模式与优化对象的系统整理。

| 代表工作 | 改进对象与机制 | 应如何解读证据 |
| --- | --- | --- |
| [ADAS，2024](https://arxiv.org/abs/2408.08435) | 元 Agent 根据历史档案编写新的 Agent 设计 | 自动系统设计；元搜索器是否更新要另外分析 |
| [SICA，2025](https://arxiv.org/abs/2504.15228) | 编码 Agent 编辑自身脚本与工具 | 作者报告随机 SWE-bench Verified 子集上 17%→53%；不能作为完整测试集结果 |
| [DGM，2025/2026](https://arxiv.org/abs/2505.22954) | 自改代码，并保留多分支的候选 Agent 档案 | 原实验报告 SWE-bench 20%→50%、Polyglot 14.2%→30.7%；属于特定设置下的系统收益 |
| [GEPA，2025/2026](https://arxiv.org/abs/2507.19457) | 从轨迹提炼语言反馈，演化提示词，维护 Pareto 候选 | 表明自然语言反馈可有效指导搜索；题目中的“超过 RL”需按相同任务与预算理解 |
| [RHI，2026-07](https://arxiv.org/abs/2607.15524) | 用成对反馈修改 Agent loop 的提示级规范 | 在 30 个合成 ML 研究任务中报告收益；并非真实科研流程普遍节省同样成本 |
| [RRSI，2026-09，10 月修订](https://arxiv.org/abs/2609.24972) | 限制编辑规模、审查特化修改、剪掉无效或昂贵变更 | 将正则化引入 Harness 提案和筛选，直接针对跨任务泛化 |

这些方法之间有三个有用的比较维度。第一，编辑空间从 prompt 到 workflow，再到任意代码逐步扩大；表达能力增加，也让评测与归因更难。第二，搜索可以是单链，也可以是保留历史分支的种群；保留暂时非最优但不同的候选，可能为后续改进保留跳板。第三，反馈可以是一个分数，也可以包含失败轨迹、异常、测试报告与语言诊断；诊断是否真正改善候选质量，需要消融。

RHI 提示了一个机制层面的方向：改善信息传递契约与上下文管理，可以比简单增加模型推理强度更划算。其“最多节省 60% 推理成本”是任务与模型配置相关的报告上限，不应当视为 Harness 优化的固定收益。[RHI 原文](https://arxiv.org/abs/2607.15524)

RRSI 更直接回应“进化是否只记住基准”。作者报告在进化使用的 split 上最多提高 6.0 个百分点、五个分布外基准上最多提高 4.3 个百分点，且相对未正则化进化减少约 30% policy tokens。policy token 数并不等于训练、搜索、工具执行在内的总体费用。[RRSI 原文](https://arxiv.org/abs/2609.24972)

**必须纳入的反向证据。** Ai2 等团队的 [Rethinking the Evaluation of Harness Evolution for Agents](https://arxiv.org/abs/2607.12227)指出，Harness 搜索应与相同反馈和推理预算下的简单搜索比较，且搜索题与最终测试题需要分开。2026-10-05 的 v4 同时报告：在 Terminal-Bench 2.1 上未超过简单 test-time scaling、泛化有限；在 ARC-AGI-3 和 EdgeBench 长程游戏中，则观察到预算匹配后的正收益。可成立的结论是其收益依赖场景，不能概括成“自动进化普遍有效”或“普遍无效”。

**本文判断：** 短任务中，一个弱初始 Harness 的缺陷可能被一次工程修复解决，持续搜索的额外收益有限。长程、状态持续变化且反馈细粒度的环境，为可继承的适应机制留下更大空间。前者是应加入的对照假设；后者与上述 v4 的实验观察一致，但仍需要更多独立任务族验证。

**七、路线 D：参数、数据和课程的自我改进**

模型层的共同目标，是把采样、筛选、修订或交互得到的信号写入权重，使收益在下一次推理时保留。这里应追问“新增学习信号来自哪里”，而不能只看训练数据是否由模型生成。

| 子路线 | 代表工作 | 学习信号及主要边界 |
| --- | --- | --- |
| 自生成推理后筛选 | [STaR，2022](https://arxiv.org/abs/2203.14465) | 生成并筛选推理，利用正确性信号及答案信息引导改进；存在外部监督锚点 |
| 迭代自对弈 | [SPIN，2024](https://arxiv.org/abs/2401.01335) | 区分旧模型回答与已有人工示范；无需新增人工标注，不等于无人工数据 |
| 自奖励 | [Self-Rewarding LMs，2024](https://arxiv.org/abs/2401.10020) | 模型生成偏好/奖励并迭代 DPO；需检查自评与独立质量的一致性 |
| 可验证奖励强化学习 | [DeepSeek-R1，2025](https://arxiv.org/abs/2501.12948) | 用规则或执行验证驱动训练；训练管线仍主要由人设计，R1 与 R1-Zero 也应区分 |
| 自出题、自解题 | [Absolute Zero，2025](https://arxiv.org/abs/2505.03335) | 自生成课程，代码执行器验证任务与答案；零新增外部任务数据并不消除环境设计 |
| 测试时强化学习 | [TTRL，2025](https://arxiv.org/abs/2504.16084) | 从无标签测试题采样与多数共识估计奖励；相关错误可能形成错误共识 |
| 自修订转密集监督 | [SD-Zero，2026-04](https://arxiv.org/abs/2604.12002) | 把二值反馈条件下的修订能力蒸馏回生成器；仍使用可验证奖励 |
| 动态自蒸馏 | [DCE+SRCL，2026-09](https://arxiv.org/abs/2609.30652) | 让特权教师副本跟随学生更新，并用验证后的简洁改写训练；教师上下文含真实答案 |
| 自合成特权信息 | [OPST，2026-10](https://arxiv.org/abs/2610.32770) | 从粗粒度主题生成问题与推理，再进行自训练；研究减少人工任务监督的可能性 |

“自己教自己”之所以可能有用，至少有四种不同原因：采样与验证选出低概率的正确行为；反馈让修订器获得比初始回答更多信息；长推理或特权上下文产生可蒸馏的较强行为；课程把训练集中在可学习的边界。它们带来的信息与计算条件不同，不能统一解释成封闭系统凭空产生可靠知识。

这里尤其要区分三件事：没有更强外部教师、没有外部答案、没有外部世界反馈。一个系统可能满足第一项，却依赖第二或第三项。例如 DCE+SRCL 没有必要使用更强模型作为教师，但其教师副本可见答案。[DCE+SRCL 原文](https://arxiv.org/abs/2609.30652)

对参数自改进的评估，除固定题集的 pass@1，还应报告相同采样预算下的 pass@k、输出长度、训练及验证成本、未训练任务的能力保持。pass@1 增长可能反映已知行为更稳定地被调用；是否扩展可达能力，还需要更充分的多样性与泛化分析。不能把一个 pass@k 指标单独当作“创造新能力”的充分证据。

**八、路线 E：Harness 与 Policy 联合进化——让改进作用于多个耦合组件**

[ SIA ](https://arxiv.org/abs/2605.27276)让 Feedback-Agent 根据任务轨迹选择更新 scaffold 或权重，在法律分类、GPU kernel 优化和单细胞去噪三个设置中比较两种更新手段。[Continual Harness](https://arxiv.org/abs/2605.09998)则在持续交互中修改 prompt、子 Agent、技能与记忆，并扩展到参数训练。它们让“本轮该改什么”成为可研究的调度问题，而不是先固定一种更新表面。

10 月的 [Self-HPO](https://arxiv.org/abs/2610.22791)把这个闭环组织得更清晰：当前策略分析失败并提出 Harness；在选出的 Harness 下做 RL；新策略再提出下一版 Harness。作者报告 Qwen3.5-35B-A3B 在三个编码基准上的平均解决率由 57.8% 提高至 64.8%，并进行组件交叉配对与分布外评估。这提供了联合收益与递归耦合的具体证据；是否长期提高改进器效率，仍应独立测量。

[R²Orch](https://arxiv.org/abs/2610.22740)则把失败提炼成技能、技能内化进参数，并在受控比较下撤回已无额外帮助的技能，推动无外部技能部署。该论文 v1 为 10 月 15 日、v2 为 10 月 22 日，11 月 2 日的论文推荐日期不应误记成首次发表日期。它展示了课程、技能与参数之间的循环，但调度或训练公式保持固定时，仍需辨析哪些元能力实际上在学习。

**本文判断：** 联合优化的吸引力来自组件的相互影响：模型更新会改变需要什么 Harness，Harness 更新会改变产生什么训练轨迹。相应的难点是归因——必须比较 H-only、P-only、固定顺序、随机顺序和自适应顺序，并将搜索与训练开销放进同一预算账本。

**九、路线 F：改进器、预测器与评价器也成为优化对象**

这一层最直接接近“使改进能力本身变好”。它包含几种不同机制，不宜只用“增加了元 Agent”概括。

**STOP：把 improver 本身当作待改程序。** [Self-Taught Optimizer](https://arxiv.org/abs/2310.02304)从一个调用 LLM 改程序的 seed improver 出发，让它改进自身，再测下游程序优化效果。其历史意义是：可执行的搜索策略本身就是学习介质。基础 LLM 保持不变，结论适用于受测程序任务，不代表模型权重递归训练。

**Hyperagents：把任务 Agent 与元 Agent 放进同一可编辑程序。** [Hyperagents](https://arxiv.org/abs/2603.19461)的关键，是修改后续版本的机制本身也可变。作者报告元层记忆、性能追踪等更新，以及跨任务域的迁移与跨运行累积。它比仅改任务解答更接近可检验的元改进；“潜在适用于任意可计算任务”属于框架表达能力，不能直接读作已验证的通用能力。

**AIDE²：直接把 AI 科研 Agent 的效率作为目标。** [原论文](https://arxiv.org/abs/2609.26457)报告 8 天自主运行产生七次连续改进，并在四个未用于选择的外部基准上获得迁移收益。这里“改进研究效率”比“多写出一份成果”更接近 RSI 的目标。需要注意，[作者博客](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)与论文中的部分 benchmark 数量、reward-hacking 数字存在不同表述，因此本文不混用这些版本的百分比。

AIDE² 的一个重要后续检验，是将发现的 Agent 放到外层，测试它能否成为更好的改进器。作者认为该 ignition test 没有给出充分证据，效率差异也未达统计显著。因此，外部任务迁移和科研效率提升，可以与“尚未证明递归点火”同时成立。Weco 的 Level 0—3 是其自定义梯度，不能与其他论文的 L1—L5 直接对应。

**MetaRSI：跨 Data、Harness、Model 的算子组合。** [MetaRSI / RSI²](https://arxiv.org/abs/2609.06396)同时组织三类更新，优化算子顺序及内部提案策略，再在元层更新调度。作者报告在 35B 总参数、3B 激活参数的目标模型上，四项基准平均比冻结起点高 10.9 个百分点，比最强固定组合基线高 3.6 个百分点。相对于固定组合的增益，更有助于判断元调度的实际贡献；这些结果仍来自作者实验，不能单凭框架命名判定已实现通用 RSI。

**RSIFlow：从改进结果中学习如何编排下一次改进。** [RSIFlow](https://arxiv.org/abs/2610.21791)诊断失败后选择组件级工作流，并把工作流结果沉淀为元 Agent 的技能和跨组件原则。它强调改进路径应随瓶颈变化，提供了研究“何时改模型、何时改外部系统”的另一种机制。其最终成绩仍须和元 Harness 更新的单独作用区分。

**预测与提前筛选：减少昂贵的无效候选。** [Predict Before You Modify](https://arxiv.org/abs/2610.13991)维护可编辑的 Improvement Dynamics Model，用历史修改及效果学习预测候选收益。[SpecRSI](https://arxiv.org/abs/2610.16491)在前代完全评估前草拟后继 Agent，但要求完成真实验证后才能接纳。两者把评估预算分配提到核心位置：预测可以帮助排队和提案，最终收益仍需独立验证。

**递归强化评价标准：让奖励更难被利用。** [Recursive Reward Improvement](https://arxiv.org/abs/2610.21040)针对开放式任务，先让对抗 Agent 构造钻 rubric 空子的答案，再修复 rubric；发现的漏洞还用于修改未来任务和标准的生成方式。这把评估器纳入进化。它提供了超越简单选择题判分的研究方向，同时要求额外检查：改进后的 rubric 是否更符合独立专家判断，而不是只适应已见攻击。

**优化训练过程本身。** [RSI-Opt](https://arxiv.org/abs/2610.32026)让元 Agent 根据既往训练实验修改提示、操作手册、测试过的优化器代码与决策节奏，并报告跨任务、跨模型的迁移。它说明改进器可以作用于训练控制，不限于编码任务；评测时需把额外 LLM 调用、代理实验和策略维护成本算进去。
